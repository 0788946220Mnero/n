# DiyarPOS — الاتصال (سيرفر ميرو السحابي + المحلي) وخادم الصور

القرار الذي اعتُمد: **سيرفر ميرو السحابي هو الخادم الأساسي وقاعدة البيانات الوحيدة**. على جهاز الكاشير يعمل جزء محلي يخص البيع والصور فقط، ولا توجد قاعدة بيانات محلية.

## 1) المخطط

```
                         الإنترنت (HTTPS فقط)
 ┌──────────────────────────────────────────────────────────────────────┐
 │  سيرفر ميرو السحابي: خادم ديار (Node/Express)  ──────────  MongoDB Atlas          │
 │   • /api/*  (الطلبات، المستخدمون، الصلاحيات، الولاء...)   القاعدة الوحيدة │
 │   • /api/health  ← الخادم + القاعدة (db.state)                         │
 │   • /api/image-cloud/relay/media/*  ← صور للعامة عبر النفق              │
 │   • /api/image-cloud/relay/ws       ← النفق (WebSocket)                 │
 └───────▲───────────────▲──────────────────────────▲───────────────────┘
         │ API            │ صور (عبر النفق)            │ WebSocket طالع من الجهاز
 ┌───────┴──────┐  ┌──────┴───────┐        ┌─────────┴──────────────────────────────┐
 │ لوحة التحكم   │  │ موقع الزبائن  │        │ جهاز الكاشير (Windows) — DiyarPOS 1.5.0  │
 │ Netlify       │  │ Netlify       │        │  • WebView: لوحة التحكم (Netlify)        │
 └──────────────┘  └──────────────┘        │    صور النفق ← تُقدَّم من ImageStorage     │
                                            │    المحلي أولاً، والإنترنت إن لم تكن عنده  │
                                            │  • شاشة البيع الأصلية: لقطة الأصناف +     │
                                            │    طابور المبيعات بلا إنترنت (JSON)       │
                                            │  • ImageStorage 127.0.0.1:5080 (الصور     │
                                            │    والمصغّرات على القرص)                  │
                                            │  • مزامنة الصور بين الأجهزة :7443 (LAN)   │
                                            └────────────────────────────────────────┘
```

- لا يتصل سيرفر ميرو السحابي بالجهاز من تلقاء نفسه. **الجهاز هو الذي يفتح اتصالاً طالعاً** (WebSocket) إلى سيرفر ميرو السحابي، ويمر عبره كل ما يخص الصور. لذلك لا حاجة لفتح أي منفذ في الراوتر.
- قاعدة البيانات لا تُفتح للإنترنت ولا للشبكة المحلية، فهي على Atlas فقط.

## 2) أوضاع الاتصال (زر «🔌 الاتصال» في DiyarPOS)

| الوضع | أين يذهب البيع | عند فشل الشبكة |
|---|---|---|
| **تلقائي** (الافتراضي) | سيرفر ميرو السحابي. إن أظهر فحص خلال آخر دقيقة أن الخادم أو قاعدته لا ترد، يُحفظ على الجهاز فوراً | يُحفظ على الجهاز بنفس المعرّف |
| **سيرفر ميرو السحابي** | سيرفر ميرو السحابي دائماً | يُحفظ على الجهاز (لا يضيع) |
| **محلي فقط** | يُحفظ ويُطبع على الجهاز | يُزامَن في الخلفية حين يتاح سيرفر ميرو السحابي |

قواعد ثابتة:
- القرار يُحسم **مرة واحدة** عند «تأكيد»، ولا يتغيّر أثناء البيع أو الدفع.
- لكل بيع معرّف فريد (`clientRef`) من بدايته. إن انتهت المهلة ولم تُعرف النتيجة، يُحفظ البيع ويُزامَن لاحقاً بالمعرّف نفسه، والخادم لا يقبل المعرّف مرتين، فلا يتكرر البيع. لا يُرسل بيع إلى خادمين.
- «الخادم يرد» لا يعني «القاعدة تعمل». الشريط يفصل بين الحالتين: «سيرفر ميرو السحابي ⚠» تعني أن الخادم يرد وقاعدة البيانات لا ترد.
- البيع المحلي لا يُحذف من الجهاز إلا بعد أن يؤكد الخادم حفظه.

مصدر البيانات الأساسي:
- **سيرفر ميرو السحابي/Atlas:** الأصناف، الأسعار، الطلبات، الجرد، المستخدمون، الأدوار، الصلاحيات، الولاء، والإعدادات.
- **الجهاز:** لقطة للقراءة فقط من الأصناف وإعدادات الطباعة، ومبيعات بانتظار المزامنة (`pending-sales.json`)، وملفات الصور.
- **التعارض:** المبيعات المحلية تُضاف فقط ولا تستبدل شيئاً. صنف حُذف قبل المزامنة يجعل البيع «مرفوضاً» ويظهر للمراجعة، ولا يُحذف تلقائياً.

## 3) أسباب الأعطال التي وُجدت فعلاً، وإصلاحها

1. **«لم تُفعَّل بعد — جهاز الصور لا يرد على Https://images.diyaralanbat.com»**
   - **السبب:** حقل «الرابط العام» في DiyarPOS فيه دومين لا يعمل خلفه شيء (`cloudflared` غير موجود). الخادم كان يختبر هذا الرابط وحده للأبد، مع أن النفق عبر سيرفر ميرو السحابي كان متصلاً.
   - **الإصلاح (`d9f0457`):** إن لم يرد الرابط العام والنفق يعمل، يُستخدم النفق تلقائياً مع رسالة بالسبب، ويُرسل رابط النفق للجهاز فيستبدل الرابط الميت عنده.
2. **تعارض المنفذ 5080 في نسخة LAN suite:** الباك إند المحلي `PORT=5080` وخادم الصور `Port=5080` على المنفذ نفسه، وشاشة الكاشير تفتح `localhost:5080/admin/`. من يبدأ أولاً يأخذ المنفذ ويفشل الآخر، فيظهر «مخزن الصور جاهز والكاشير لا يستجيب». هذه النسخة لم تُعتمد (انظر القسم 8).
3. **فشل استيراد Cloudinary:** للنقل سببان.
   - النقل يحتاج سحابة مفعّلة، والسحابة لم تتفعّل بسبب العطل رقم 1، فكان يرفض بـ «فعّل سحابة الصور أولاً».
   - كان يعلن «اكتمل» ولو فشلت معظم الصور، ويستبدل الروابط دون أن يتحقق أنها تُعرض.
   - **الإصلاح (`5e4f5df`):** يتحقق من عرض كل صورة قبل استبدال رابطها، ويعدّ الروابط الباقية في القاعدة فعلاً، ويقول «جزئي» مع السبب.
4. **الرجوع الصامت إلى Cloudinary:** معطّل الآن. الصورة إمّا تُحفظ على السحابة المحلية، وإمّا تُرفض برسالة.
5. **رسائل الرفض كانت تظهر «حدث خطأ في الخادم»:** معالج الأخطاء يقرأ `statusCode` بينما كود الرفع كان يضع `status` فقط. أصبح يضع الاثنين.
6. **غياب التشخيص:**
   - زر «تشخيص كامل» في بطاقة سحابة الصور، يقف عند أول خطوة فاشلة ويذكر سببها.
   - سجلات للنفق على سيرفر ميرو السحابي بالشكل `[image-relay] device connected/rejected…` و`[image-cloud] METHOD path -> status`، دون أسرار.
   - سجل في ImageStorage لسبب «النفق غير مضبوط».

## 5) الأوامر

```bash
# الخادم (سيرفر ميرو السحابي ينشر تلقائياً بعد git push)
npm install && npm test        # مع خادم صور حقيقي:
IMAGE_STORAGE_TEST_URL=http://127.0.0.1:5080 IMAGE_STORAGE_TEST_KEY=isk_... npm test
```
```powershell
# DiyarPOS — على Windows، من مجلد pos
powershell -ExecutionPolicy Bypass -File .\build.ps1          # ينتج DiyarPOS-Setup-1.5.0.exe
dotnet run --project tests\Connection.Tests -- https://n-production-78f4.up.railway.app http://127.0.0.1:5080
```

لوحة التحكم: اسحب مجلد `admin` إلى موقع `diyaradmin` على Netlify، ثم تأكد أن `version.json` يعرض 70.

## 6) متغيرات البيئة (سيرفر ميرو السحابي ← Variables) — الأسماء فقط

- **موجودة ولم تتغير:** `MONGO_URI`، `JWT_SECRET`، `JWT_REFRESH_SECRET`، `CLIENT_URL`، `CLOUDINARY_*` (للفيديو والصور القديمة حتى تُنقل)، `PUBLIC_API_URL`.
- **`ADMIN_PASSWORD`:** مطلوبة **فقط** لقاعدة فارغة، لا لقاعدتك الحالية. يجب أن تكون 8 أحرف أو أكثر، ولا يوجد افتراضي معروف.
- **لا متغيرات جديدة لهذه المهمة.**
- **على جهاز Windows:** الإعدادات في `%LOCALAPPDATA%\DiyarPOS\` (`connection.json`، `imagecloud.json`). فيها أسرار الجهاز، فلا تُشارك ولا تُرفع إلى Git.

## 7) الضبط خطوة بخطوة

1. **في DiyarPOS ← سحابة الصور:** **امسح حقل «الرابط العام»**، لأن `images.diyaralanbat.com` لا يعمل بلا Cloudflare، ثم اضغط «حفظ وتشغيل».
2. **في لوحة التحكم ← الإعدادات ← سحابة الصور ← «تشخيص كامل»:** يجب أن تظهر الخطوات العشر بعلامة ✓. أي ✗ تذكر السبب.
3. **«انقل كل الصور الآن»** بعد نجاح التشخيص. النتيجة «✓ اكتمل» أو «⚠ لم يكتمل» مع السبب.
4. **زر «🔌 الاتصال»:** اتركه على «تلقائي». و«اختبار سيرفر ميرو السحابي» يجب أن يعطي «متصل — قاعدة البيانات تعمل».

**المنافذ:**
- المثبّت يفتحها إن اخترت «السماح لأجهزة الشبكة المحلية».
- يدوياً: `C:\Program Files\DiyarPOS\tools\Open-DiyarPOS-Port.ps1`، وللإغلاق `Close-DiyarPOS-Port.ps1`.
- تُفتح على شبكة Private ومن LocalSubnet فقط.
- **لا تفتح أي منفذ في الراوتر.**

## 8) جهاز Windows آخر

1. ثبّت `DiyarPOS-Setup-1.5.0.exe`، وفيه WebView2 والنفق.
2. افتح DiyarPOS وسجّل الدخول. يصل إلى لوحة التحكم ← سحابة الصور «طلب ربط»، فاضغط «موافقة».
3. على الشبكة نفسها تتزامن الصور بين الأجهزة عبر المنفذ 7443. على شبكة أخرى تعمل الصور عبر النفق، والخادم يجرّب كل جهاز متصل قبل أن يرد بـ 404.

## 9) نسخة «LAN suite» التي أرسلتها: ما أخذتُه وما لم آخذه

**أخذتُ:**
- سجلات تشخيص النفق.
- منع كلمة المرور الافتراضية للمدير.
- إظهار رابط النفق في اللوحة.
- سجل سبب «النفق غير مضبوط» في RelayClient.

**لم آخذ:**
- **الباك إند المحلي + MongoDB محلية:** قاعدة فارغة منفصلة عن Atlas، بلا مزامنة. المبيعات فيها لا تصل إلى الموقع ولا إلى الجرد. هذا يخالف القرار المعتمد.
- **المنفذ 5080 للباك إند:** يتعارض مع خادم الصور.
- **إزالة نطاقات سيرفر ميرو السحابي من CORS وتعطيل `trust proxy`:** كانت ستكسر الموقع ولوحة Netlify وحدود المحاولات على سيرفر ميرو السحابي.
- **التراجع عن إصلاحات Cloudinary والنقل:** النسخة كانت مبنية على كود أقدم من الإصلاحات.

ملفاتها (BackendManagerWindow وغيرها) باقية في ملفك كما هي، ولم يُحذف منها شيء.

**يحتاج إعداداً يدوياً:**

- رفع الكود إلى GitHub، ونشر لوحة التحكم v70.
